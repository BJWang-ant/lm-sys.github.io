## TL;DR

On eight H20-3e GPUs with four for prefill and four for decode, our combined configuration reduced mean end-to-end latency from **13.63 s to 4.69 s (65.57%)** and increased output throughput from **846.76 to 2,446.18 tokens/s (188.89%)**. Prefill context parallelism and decode data parallelism provided the largest step. FP8 DeepGEMM scoring then cut the time spent in the prefill Indexer.

## Measurement Setup

The router sends each request through prefill and decode. The workers transfer the KV state directly over intra-node Mooncake NVLink. The baseline runs TP4 attention and EP4 MoE on both workers with eager BF16 Torch prefill scoring. Every run uses the same DeepSeek-V4.1-Flash checkpoint, Humming MoE backend, DSpark block size 5, 8,192-token prefill chunks, and a 0.25× host cache on prefill.

| Workload | Value |
| --- | --- |
| Requests and concurrency | 256 requests, 24 in flight |
| Nominal input | 61,440 shared tokens + 4,096 request-specific tokens |
| Output | 500 tokens per request |
| Cache protocol | 10 warmup requests, then a cache flush before measurement |
| Observed cache hit rate | 93.21% |

Each comparison adds one change to the preceding configuration. Each result comes from a single run with all 256 requests and 128,000 output tokens completed.

## 1. Prefill CP and Decode DP

Prefill handles many token rows from a single long request. Interleaved context parallelism assigns those rows to different ranks so the four GPUs can work on the same request. Decode has many active requests with a small number of query rows each. Data-parallel attention and a data-parallel LM head assign independent requests to different ranks.

![Prefill partitions one prompt across four ranks while decode assigns requests to ranks](/images/blog/deepseek-v41-h20/pd-parallelism.svg)

**Serving result.** Mean E2E went from **13,633.80 to 7,547.46 ms (−44.64%)**. Output throughput rose from **846.76 to 1,537.90 tokens/s (+81.62%)**.

## 2. FP8 DeepGEMM for the Prefill Indexer

The Indexer scores visible keys before selecting a small subset for attention. On Hopper, we gather each request's packed FP4 keys once, convert the queries and keys to E4M3, and call DeepGEMM's `fp8_mqa_logits` for every prefill Indexer layer. The scorer masks positions beyond each query's causal boundary, and candidate consumers keep their original candidate set.

The gather applies each FP4 block's UE8M0 scale in FP32. Before casting to E4M3, it clamps the scaled values to the format's finite range, **−448 to +448**. DeepGEMM receives unit key scales because the block scales have already been applied. Values outside the range saturate at the boundary.

![Packed FP4 keys are scaled and clamped before FP8 scoring](/images/blog/deepseek-v41-h20/fp8-indexer.svg)

**Serving result.** Mean E2E went from **7,547.46 to 5,294.89 ms (−29.85%)**. Output throughput rose from **1,537.90 to 2,200.82 tokens/s (+43.11%)**. [SGLang PR #49066](https://github.com/sgl-project/sglang/pull/49066)

## 3. Breakable CUDA Graphs for Prefill

Long prefill runs launch many small kernels. Breakable CUDA Graphs capture the graph-safe stretches and replay them together, while operations that need live metadata stay eager. Bounded SWA replay captures separate buckets for the shorter decoder tail, avoiding work on the full prefill chunk in later layers.

![Graph-safe kernel segments replay around the eager Indexer](/images/blog/deepseek-v41-h20/breakable-graphs.svg)

**Serving result.** Mean E2E went from **5,294.89 to 5,100.87 ms (−3.66%)**. Output throughput rose from **2,200.82 to 2,290.05 tokens/s (+4.05%)**. [SGLang PR #43089](https://github.com/sgl-project/sglang/pull/43089)

## 4. Tensor-Parallel MoE

With expert parallelism, one rank can receive more routed tokens than its peers and delay the output collective. With tensor-parallel MoE, each rank holds a slice of every expert. All ranks share the work for a hot expert while using the same Humming backend.

![Expert placement versus weight shards of every expert](/images/blog/deepseek-v41-h20/tp-moe.svg)

**Serving result.** Mean E2E went from **5,100.87 to 4,902.85 ms (−3.88%)**. Output throughput rose from **2,290.05 to 2,380.37 tokens/s (+3.94%)**.

## 5. Larger Indexer Score Tiles

The Indexer limits the size of its temporary score matrix. At long context lengths, a small budget fits few queries, so scoring and selection repeat across many tiles. Increasing the prefill budget from **64 MiB to 2 GiB** lets each tile cover more queries. The experimental decode scorer has a separate budget and can use **512 MiB instead of 128 MiB**. The comparison below changes the prefill budget only.

![A larger score tile processes more query rows per scoring and selection pass](/images/blog/deepseek-v41-h20/score-budget.svg)

**Serving result.** Mean E2E went from **4,902.85 to 4,827.67 ms (−1.53%)**. Output throughput rose from **2,380.37 to 2,426.16 tokens/s (+1.92%)**. [SGLang PR #49067](https://github.com/sgl-project/sglang/pull/49067)

## 6. Fuse Prefill Selection and Writeback

The Indexer needs both candidate block IDs for later layers and physical KV slots for attention. Triton combines block reduction and selection so the publisher does less intermediate work. A separate fused writeback filters invalid picks, sorts the remaining positions, and translates them to KV slots in one launch.

![The candidate publisher and selection writeback each combine several tensor operations](/images/blog/deepseek-v41-h20/selection-fusion.svg)

**Serving result.** Mean E2E went from **4,827.67 to 4,760.91 ms (−1.38%)**. Output throughput rose from **2,426.16 to 2,464.74 tokens/s (+1.59%)**. [SGLang PR #49069](https://github.com/sgl-project/sglang/pull/49069)

## 7. Reuse Paged Indexer K Tiles During Verification

DSpark verifies several query rows from the same request in one forward pass. Those rows look at nearly the same keys. The paged scorer loads and dequantizes one FP4 K tile into BF16, then reuses it for the request's query rows. Each row still applies its own causal limit.

![Multiple verification queries reuse one dequantized key tile](/images/blog/deepseek-v41-h20/verify-reuse.svg)

**Serving result.** Mean E2E went from **4,760.91 to 4,705.99 ms (−1.15%)**. Output throughput rose from **2,464.74 to 2,480.23 tokens/s (+0.63%)**. [SGLang PR #49068](https://github.com/sgl-project/sglang/pull/49068)

## 8. Poll the Final KV Transfer

Prefill can finish its compute while the final KV transfer is still in flight. We let the prefill worker wait up to **5 ms** for completion before its regular rank-consensus poll. A completion or failure wakes the waiter early. If a transfer is about to finish, the request can reach decode one scheduler round sooner.

![A short completion wait can avoid another scheduler round](/images/blog/deepseek-v41-h20/final-poll.svg)

**Serving result.** Mean E2E went from **4,705.99 to 4,693.58 ms (−0.26%)**. Output throughput went from **2,480.23 to 2,446.18 tokens/s (−1.37%)**. We retained this setting for the lowest mean E2E in the sweep.

## Reproduction

Use SGLang revision `91afc4f363cc60ca0bf98d38e87cc6cfa32062fe` from the experiment branch and set `MODEL_PATH` and `DATASET_PATH` to your local DeepSeek-V4.1-Flash checkpoint and ShareGPT dataset. Start prefill and decode in separate terminals for either configuration. Run the same router and benchmark commands for both.


Use this setup in both worker terminals.

```bash
export SGLANG_ENABLE_DSV41_ENGRAM_HOST_TABLE=1
export SGLANG_DSV41_ENGRAM_HOST_TABLE_LAYOUT=per_rank
export SGLANG_HUMMING_INPUT_QUANT_CONFIG='{"dtype":"float8e4m3"}'
export SGLANG_USE_CUDA_IPC_TRANSPORT=1
export SGLANG_MM_FEATURE_CACHE_MB=512
export SGLANG_VLM_CACHE_SIZE_MB=512
export SGLANG_DSV41_SM90_PREFILL_INDEXER=deepgemm
export SGLANG_OPT_DSV41_DECODE_INDEXER_FP8=0
export SGLANG_OPT_DSV41_LARGE_INDEXER_SCORE_BUDGET=0
export SGLANG_HOST_IP=127.0.0.1
export SGLANG_MOONCAKE_CUSTOM_MEM_POOL=INTRA_NODE_NVLINK
export MC_INTRA_NVLINK=true
export MC_INTRANODE_NVLINK=true
export SGLANG_DISAGGREGATION_ALL_CP_RANKS_TRANSFER=1
export SGLANG_OPT_MOONCAKE_NVLINK_LAYER_BATCH=0
export SGLANG_SET_CPU_AFFINITY=1
export SGLANG_JIT_DEEPGEMM_FAST_WARMUP=1

SERVE=(
  python3 -m sglang.launch_server --model-path "$MODEL_PATH"
  --served-model-name llm --trust-remote-code --host 127.0.0.1
  --attention-backend dsv4 --moe-runner-backend humming
  --mm-feature-transport cuda_ipc --reasoning-parser auto --tool-call-parser auto
  --speculative-algorithm DSPARK --speculative-dspark-block-size 5
  --enable-cache-report --enable-metrics --enable-strict-thinking --random-seed 42
  --tp 4 --tokenizer-worker-num 8 --detokenizer-worker-num 8 --moe-a2a-backend none
  --disaggregation-transfer-backend mooncake
)
PREFILL=(
  --enable-hierarchical-cache --hicache-ratio 0.25 --hicache-io-backend kernel
  --hicache-write-policy write_through --language-model-only
  --chunked-prefill-size 8192 --max-prefill-tokens 8192
  --enable-decoder-swa-bounded-replay --swa-full-tokens-ratio 0.1
  --mem-fraction-static 0.8 --disaggregation-mode prefill
  --disaggregation-bootstrap-port 8998 --port 9091
)
DECODE=(
  --mem-fraction-static 0.85 --max-running-requests 256
  --disaggregation-mode decode --port 9092
)
BASELINE=(
  SGLANG_DSV41_TORCH_PREFILL_INDEXER=1
  SGLANG_OPT_DSV41_VERIFY_INDEXER_K_REUSE=0
  SGLANG_OPT_DSV41_VERIFY_INDEXER_BF16_K_REUSE=0
  SGLANG_OPT_DSV41_TRITON_PREFILL_SELECTION=0
  SGLANG_OPT_DSV41_LARGE_PREFILL_SCORE_BUDGET=0
  SGLANG_MOONCAKE_FINAL_POLL_TIMEOUT_MS=0
)
OPTIMIZED=(
  SGLANG_DSV41_TORCH_PREFILL_INDEXER=0
  SGLANG_OPT_DSV41_VERIFY_INDEXER_K_REUSE=1
  SGLANG_OPT_DSV41_VERIFY_INDEXER_BF16_K_REUSE=1
  SGLANG_OPT_DSV41_TRITON_PREFILL_SELECTION=1
  SGLANG_OPT_DSV41_LARGE_PREFILL_SCORE_BUDGET=1
  SGLANG_MOONCAKE_FINAL_POLL_TIMEOUT_MS=5
)
```

### Baseline prefill

```bash
env "${BASELINE[@]}" CUDA_VISIBLE_DEVICES=0,1,2,3 "${SERVE[@]}" "${PREFILL[@]}" \
  --disable-prefill-cuda-graph --ep-size 4
```

### Baseline decode

```bash
env "${BASELINE[@]}" CUDA_VISIBLE_DEVICES=4,5,6,7 "${SERVE[@]}" "${DECODE[@]}" \
  --ep-size 4
```

### Optimized prefill

```bash
env "${OPTIMIZED[@]}" CUDA_VISIBLE_DEVICES=0,1,2,3 "${SERVE[@]}" "${PREFILL[@]}" \
  --enable-prefill-cp --cp-strategy interleave \
  --cuda-graph-backend-prefill breakable --cuda-graph-max-bs-prefill 8192 \
  --cuda-graph-prefill-max-context 262144 --ep-size 1
```

### Optimized decode

```bash
env "${OPTIMIZED[@]}" CUDA_VISIBLE_DEVICES=4,5,6,7 "${SERVE[@]}" "${DECODE[@]}" \
  --dp 4 --enable-dp-attention --enable-dp-lm-head --ep-size 1
```

### Router

Start the router after both workers are healthy. Run the benchmark when the router reports readiness.

```bash
python3 -m sglang_router.launch_router --pd-disaggregation \
  --prefill http://127.0.0.1:9091 8998 --decode http://127.0.0.1:9092 --host 127.0.0.1 \
  --port 9090 --worker-startup-timeout-secs 3600 --disable-circuit-breaker \
  --prefill-policy round_robin --decode-policy round_robin
```

### Benchmark

```bash
python3 -m sglang.bench_serving \
  --model "$MODEL_PATH" \
  --served-model-name llm --host 127.0.0.1 --port 9090 --backend sglang-oai \
  --dataset-name generated-shared-prefix \
  --dataset-path "$DATASET_PATH" \
  --num-prompts 256 --gsp-num-groups 1 --gsp-prompts-per-group 256 \
  --gsp-system-prompt-len 61440 --gsp-question-len 4096 --gsp-output-len 500 \
  --max-concurrency 24 --warmup-requests 10 --seed 42 --flush-cache --cache-report
```

## Colocated Serving on Four H20s

The final measured colocated stack combined FP8 DeepGEMM prefill scoring, breakable prefill graphs, TP MoE, paged K-tile reuse, and batch-wise prefill CP with decode DP. Against the four-GPU TP4 baseline with DSpark, mean E2E went from **12,563.99 to 7,957.13 ms (−36.67%)**, and output throughput rose from **947.11 to 1,482.72 tokens/s (+56.55%)**.

A colocated worker shares its four ranks between prefill and decode. During prefill it splits the batch's token rows across the ranks. During decode and target verification it gives each rank its own query rows and all attention heads, then gathers attention outputs back into batch order. The scheduler and KV state stay on the same worker.

![One four-GPU worker uses context parallelism during prefill and query data parallelism during decode](/images/blog/deepseek-v41-h20/colocated-cp-dp.svg)

Adding decode DP to the prefill CP configuration reduced mean E2E from **8,632.46 to 7,957.13 ms (−7.82%)** and raised output throughput from **1,377.49 to 1,482.72 tokens/s (+7.64%)**. [SGLang PR #45729](https://github.com/sgl-project/sglang/pull/45729)
